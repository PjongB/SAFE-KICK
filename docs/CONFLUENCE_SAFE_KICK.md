# SAFE-KICK 시스템 설계 및 통합 테스트

이 문서는 SAFE-KICK 프로젝트를 Confluence에 공유하기 위한 요약 문서입니다.
Confluence 새 페이지에 본문을 붙여넣은 뒤 담당자와 상태만 팀 상황에 맞게
수정하면 됩니다.

| 항목 | 내용 |
|---|---|
| 프로젝트 | SAFE-KICK 전동 킥보드 안전 시스템 |
| 현재 상태 | 백엔드 연동 전 STM32-Raspberry Pi 통합 테스트 |
| 최종 수정 | 2026-08-13 |
| 저장소 | [PjongB/SAFE-KICK](https://github.com/PjongB/SAFE-KICK) |

## 1. 목적과 범위

SAFE-KICK은 앱 인증과 음주 검사를 통과한 사용자만 킥보드를 이용하게 하고,
주행 중 2인 탑승이 의심되면 부저 경고 후 잠그는 안전 시스템입니다.

현재 범위는 Raspberry Pi 서버와 STM32 펌웨어의 통합입니다. 실제 앱과
백엔드는 아직 연결하지 않았으며 FastAPI 테스트 API가 인증 이벤트를
대체합니다.

## 2. 시스템 구성

| 구성 요소 | 역할 |
|---|---|
| 앱/백엔드 | QR 연결, 회원 인증, 인증 완료 이벤트 전달. 현재 미연동 |
| Raspberry Pi | 세션 상태, 판단 로직, REST API, STM32 UART 제어 |
| STM32F411RE | 센서 측정, 릴레이·부저 제어, UART 응답 |
| MQ-3 | 음주 검사에 사용할 가스값 측정 |
| HX711 + 로드셀 4개 | 탑승 무게 측정 |
| 릴레이 / 부저 | 주행 가능 여부 제어 / 위험 경고 |

```text
앱/백엔드
  -> 인증 완료 이벤트
Raspberry Pi FastAPI
  -> UART 115200-8-N-1
STM32F411RE
  -> MQ-3, 로드셀 4개, 릴레이, 부저
```

## 3. 전체 동작 흐름

```text
STM32 연결
-> LOCK / LOCK_OK
-> 앱 사용자 인증 완료
-> CHECK_MQ3
-> 음주 검사 통과
-> 무게 검사 요청 대기
-> CHECK_WEIGHT
-> 안정된 1인 탑승 확인
-> UNLOCK / UNLOCK_OK
-> 주행 중 무게 감시
-> 2인 탑승 의심 시 BUZZ_ON
-> 상태가 계속되면 LOCK
```

음주 검사 직후 무게 측정을 자동 시작하지 않습니다. 테스트 단계에서는
`POST /test/weight-check` 요청을 받은 뒤에만 시작하며, 백엔드 연결 후에는
이 요청을 실제 앱 또는 백엔드 이벤트로 교체합니다.

## 4. 상태 정의

| 상태 | 설명 |
|---|---|
| `locked` | 초기 잠금 상태 |
| `checking_alcohol` | MQ-3 검사 중 |
| `waiting_weight_check` | 탑승 무게 검사 요청 대기 |
| `checking_weight` | 1인 탑승 안정값 확인 중 |
| `monitoring` | 잠금 해제 후 주행 무게 감시 |
| `warning` | 부저 경고 중 |
| `locked_by_safety` | 안전 판단에 따른 강제 잠금 |

## 5. 판단 정책

### 5.1 음주 검사

- 초기 기준값 이후 8개 샘플을 수집합니다.
- 기준값보다 `100` 이상 높은 샘플을 양성으로 봅니다.
- 양성 샘플이 5개 이상이면 음주 위험으로 판단합니다.
- 기준값, 샘플, 양성 수, 최대 변화량, 판단 이유를 상태에 저장합니다.
- MQ-3 예열과 설치 환경에 따라 현장에서 임계값을 다시 보정해야 합니다.

### 5.2 최초 1인 탑승 확인

- 약 1초 간격의 총무게 값 3개를 사용합니다.
- 세 값이 모두 `20kg 이상 100kg 이하`여야 합니다.
- 최대값과 최소값 차이가 `5kg 이하`여야 합니다.
- 통과하면 중앙값을 탑승자 기준 무게로 저장합니다.
- 튄 값이나 불안정한 값이 있으면 다시 측정합니다.
- 앞뒤 하중 비율은 사용하지 않습니다.

두 사람이 동시에 올라오거나 등록 무게를 속이는 상황은 무게만으로 완전히
구분할 수 없습니다. 현재 정책은 안정된 1인 탑승을 확인하는 1차 기준입니다.

### 5.3 주행 중 2인 탑승 감시

- 총무게가 `110kg 이상`으로 4초 유지되면 부저를 켭니다.
- 이후 10초 더 지속되면 릴레이를 잠급니다.
- 임계값 아래로 내려가면 경고 타이머를 초기화합니다.
- 임계값 부근 흔들림 방지를 위해 `2kg` 데드밴드를 사용합니다.
- 신호 대기 중 잠시 내려 무게가 낮거나 0에 가까운 것은 잠금 사유가 아닙니다.

실제 주행 중 즉시 릴레이를 끄는 것은 위험할 수 있습니다. 최종 제품에서는
속도 신호를 함께 사용해 정지 또는 저속일 때만 잠그는 정책이 필요합니다.

## 6. STM32 하드웨어

| 장치 | STM32 핀 |
|---|---|
| USART2 TX / RX | PA2 / PA3 |
| MQ-3 ADC | PA1 |
| 부저 / 릴레이 | PA6 / PA7 |
| HX711 FL DT / SCK | PB0 / PB1 |
| HX711 FR DT / SCK | PB2 / PB10 |
| HX711 RL DT / SCK | PB12 / PB13 |
| HX711 RR DT / SCK | PB14 / PB15 |

부팅 시 로드셀 영점을 잡으므로 `Tare...` 동안 발판을 비우고 `READY`가
출력된 후 테스트합니다.

## 7. UART 계약

- 통신 설정: `115200 baud`, `8 data bits`, `no parity`, `1 stop bit`
- 명령과 응답은 한 줄 단위로 처리합니다.

| Raspberry Pi 명령 | STM32 동작 | 주요 응답 |
|---|---|---|
| `LOCK` | 릴레이 잠금 | `LOCK_OK` |
| `UNLOCK` | 릴레이 잠금 해제 | `UNLOCK_OK` |
| `CHECK_MQ3` | MQ-3 측정 | 측정값과 결과 |
| `CHECK_WEIGHT` | 로드셀 측정 | `FL`, `FR`, `RL`, `RR`, `TOTAL` |
| `BUZZ_ON` / `BUZZ_OFF` | 부저 켜기 / 끄기 | 상태 응답 |

```text
FL:23.84 FR:15.42 RL:7.09 RR:5.29 TOTAL:51.64
```

## 8. 백엔드 연동 전 테스트

서버 실행 후 `http://127.0.0.1:8000/docs`의 Swagger 화면에서 진행합니다.

| 순서 | API | 확인 내용 |
|---|---|---|
| 1 | `GET /status` | STM32 연결과 초기 상태 |
| 2 | `POST /session/start` | 테스트 세션 시작 |
| 3 | `POST /test/auth-complete` | 인증 완료 대체 및 MQ-3 검사 |
| 4 | `GET /status` | 음주 검사 결과 |
| 5 | `POST /test/weight-check` | 탑승 무게 검사 시작 |
| 6 | `GET /status` | 기준 무게, 잠금 해제, 감시 상태 |
| 7 | `POST /session/end` | 세션 종료와 잠금 |
| 8 | `GET /session/summary` | 종료 결과 |

정상 잠금 해제 시 `is_locked: false`, `status: unlocked`,
`safety_state: monitoring`, `session_active: true`를 확인합니다.

잠금 테스트는 `monitoring` 상태에서 110kg 이상 하중을 유지합니다. 4초 후
부저, 추가 10초 후 잠금을 확인합니다. `GET /session/stream`은 상태를
실시간으로 보는 선택 기능이며 잠금 판단에 필수는 아닙니다.

## 10. 검증 상태

- Raspberry Pi 단위 및 Mock 통합 테스트 6개 통과
- Mac과 STM32 USART2 USB 연결 완료
- MQ-3 결과의 상태 API 조회 완료
- 수동 무게 검사 후 `UNLOCK_OK` 확인
- 주행 감시 중 실시간 로드셀 값 수신 확인

## 11. 미완료 작업

| 우선순위 | 작업 | 이유 |
|---|---|---|
| 높음 | 실제 백엔드 인증 연결 | 테스트 API를 운영 이벤트로 교체 |
| 높음 | 속도 신호 연동 | 주행 중 즉시 잠금 위험 방지 |
| 높음 | HX711 타임아웃과 고장 처리 | 센서 고장 시 무한 대기 방지 |
| 중간 | 장시간 0kg 정책 결정 | 하차, 방치, 세션 종료 구분 |
| 중간 | 무게와 시간 임계값 현장 보정 | 기체 환경에 따른 오탐 감소 |
| 중간 | 동시 탑승 탐지 보완 | 무게만으로 1인과 완전 구분하기 어려움 |

## 12. 테스트 안전

- 정지된 킥보드나 테스트 지그에서 먼저 검증합니다.
- 잠금 시험 전 바퀴를 띄우거나 모터 전원을 분리합니다.
- 로드셀 정격을 초과하는 하중을 올리지 않습니다.
- UART TX/RX를 교차 연결하고 GND를 공통으로 연결합니다.
- UART 핀에는 5V가 아닌 3.3V 레벨을 사용합니다.
